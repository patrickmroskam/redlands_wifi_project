Privacy policy

Last updated: September 20, 2026

Short version: this site maps WiFi networks — and now also Bluetooth devices — that announce themselves over the air in Redlands, CA. It publishes what they broadcast to everyone nearby, never who uses them. Devices that rotate their address to avoid being followed, which is most phones and watches, are not mapped at all. To keep your network off the map, add _nomap to the end of its name. To remove a network that is already on the map, open an issue.

About this project

The Redlands Wifi Project is a hobby project. One person travels around Redlands with a small WiFi scanner, and this site plots the networks it heard. It works like WiGLE, but only for Redlands. Everything, including the code and the map data, is public in the project's GitHub repository.

What we publish

For each WiFi network, the map shows only these details:

SSID
The network name it broadcasts (shown as "hidden" if blank).
BSSID
The hardware (MAC) address of the access point, which is broadcast with every beacon.
Auth mode
The kind of security the network advertises, such as open, WEP, or WPA2.
Channel
The radio channel the network was heard on.
Approximate location
Where the scanner was when it heard the network. This is the scanner's position on the street, not the exact spot of the router, and it can be off by many meters.
First seen
The date and time the network was first recorded for the map, by the scanner's clock.

When a network is heard again, its map entry is not changed. The map does not show how a network moves or changes over time.

For each Bluetooth device, the map shows its advertised name (often blank), its address, the approximate location, and when it was first seen — and nothing else. See Bluetooth devices for which devices are mapped at all.

Bluetooth devices

The scanner also hears Bluetooth Low Energy advertisements, the same messages your phone uses to find headphones or a speaker. They are shown on a separate map.

Most of what it hears is deliberately not published. Phones, watches and earbuds broadcast an address that they change every few minutes, precisely so that they cannot be followed from place to place. Publishing those would amount to mapping the people who walked or drove past, and the same handset would reappear as a brand new device on every pass. So only addresses that stay the same over time are mapped — the kind used by equipment that sits in one place. In the first scan that included Bluetooth, that rule dropped 39 of 57 devices heard.

Where an address cannot be told apart with certainty, it is left off the map rather than put on it.

Everything else on this page applies to Bluetooth devices exactly as it does to WiFi networks: the same two ZIP codes, the same opt-out, the same removal requests, and the same promise never to record signal strength, altitude, accuracy, or anything about the people carrying a device.

What we don't collect

  • No personal information: no names, addresses, phone numbers, or emails.
  • Nothing about the people or devices using a network: no phones, laptops, or client addresses. The Bluetooth map is not an exception — it excludes the rotating addresses that personal devices broadcast (see Bluetooth devices).
  • No passwords and no network traffic. We never see what anyone sends or receives.
  • The map does not show signal strength, altitude, or GPS accuracy. (The raw scan files do contain them; see Where we map.)

How networks are observed

WiFi access points constantly broadcast short "beacon" messages that announce their name, address, and security type to any device in range. Your phone uses these same messages to list nearby networks, and the scanner collects them the same way.

Bluetooth devices advertise themselves in much the same way, and the scanner listens for those announcements without answering them.

The scanner never connects to a network or pairs with a device, never tries to log in or guess a password, and never looks at anyone's traffic.

Where we map

The map covers only ZIP codes 92373 and 92374 in Redlands, California. Each time the map is updated, any network heard outside those two ZIP codes is thrown away and never added to the map.

To be transparent about the raw scan files:

  • They contain everything the scanner heard: networks and Bluetooth devices outside Redlands, ones that opted out, every rotating address that the maps leave out, signal strength, altitude, GPS accuracy, and the scanner's timestamped route.
  • New scan files are private. They are uploaded to a separate private repository that only the project owner can read. The daily update reads them from there, publishes only the filtered map data, and deletes the file it processed. A file that can't be read is kept, privately, until a person fixes it. Raw scan files are no longer downloadable from this site.
  • The first batch is still public. Before this changed, 48 scan files were uploaded to the public repository. They have been deleted from it, but the repository's history still keeps a copy, and anyone who copied the repository before then still has theirs. Removing them from history is destructive and has not been done.

Opting out

Add _nomap to the end of your network's name (SSID), for example MyHomeWiFi_nomap. While its name ends that way, the scanner's sightings of it are skipped and not added to the map. This works for a Bluetooth device's advertised name too, where you can change it. (_optout works too, and uppercase or lowercase doesn't matter.)

Renaming a network does not remove an entry that is already on the map. For that, send a removal request, which is remembered. The opt-out itself is not remembered: if you later remove _nomap from the name, the network can be added the next time it is heard.

Removal requests

To have a network removed from the map, open a new issue on the project's GitHub page. You do not need to email anyone. You will need a free GitHub account.

  • Include the network's BSSID (MAC address) or its name, plus the nearest street or intersection.
  • Issues are public. Don't include your name, your home address, or anything else personal.
  • A person reviews each request and removes the entry by hand.
  • The removal is remembered. The network's BSSID goes on a list of removed networks (with only the date and the issue number), and later scans never add it back, even under a different name. You don't need to rename it or add _nomap.
  • Older versions of the map data stay in the repository's history.

Visiting this site

  • No accounts and no sign-in.
  • No cookies and no local storage.
  • No analytics, ads, or trackers.

Two outside services still see a visitor's IP address:

  • GitHub Pages hosts the site, so GitHub receives each page request, including your IP address. See the GitHub privacy statement.
  • OpenStreetMap serves the map tiles. The tile servers see your IP address and which part of the map you are looking at, and this site's address, but not which page you were on. See the OpenStreetMap Foundation privacy policy.

Changes to this policy

When this policy changes, the "last updated" date at the top changes too. Every earlier version is kept in the repository's history.
